# Project Phantom — website

Marketing site for Project Phantom, published by GitHub Pages at **projectphantom.space**.

## How it deploys

- `.github/workflows/pages.yml` runs on every push to `main`. It copies the repo into `_site/`, runs
  `scripts/build-achievements.mjs` to generate `assets/achievements/achievements.json`, and publishes
  `_site/` to GitHub Pages.
- `CNAME` pins the custom domain. Do not rename or move it.
- Pages are linked **extensionless** (`/technology`, `/teams`, `/deployment`), and GitHub Pages resolves
  those from the HTML files at the repository root. The page files must stay at the root — moving them into
  a subfolder breaks every internal link, the sitemap, and the absolute `projectphantom.space/<page>` links.
- `assets/` is referenced by absolute URLs in a few places (`https://projectphantom.space/assets/…`), so the
  folder name and its file names are part of the public URL space.

## Layout

| Path | What it is |
| --- | --- |
| `index.html` | Homepage |
| `technology.html`, `mercury.html`, `deployment.html`, `teams.html`, `terms.html`, `tasks.html` | Main site pages |
| `rithishdharanidharan.html`, `meherabhossain.html`, `janaswilam.html`, `mohammedfuad.html`, `mohammedzabith.html`, `inspiredbysheikhmohammed.html` | Individual team member pages |
| `dashboard.html` | Standalone internal dashboard (single-file app) |
| `sitemap.xml` | Sitemap; update it when a public page is added or renamed |
| `assets/` | All image, logo and icon files |
| `assets/partners/` | Partner logos — `N.png` colour, `N_white.png` white silhouette, `partners.json` manifest |
| `assets/partners/raw/` | Original full-size logo masters (not served) |
| `assets/achievements/` | Achievement photos, picked up by the achievements manifest |
| `admin/` | Decap CMS entry point and its config |
| `scripts/` | Build scripts used by CI |
| `reminders/` | Standalone Node package used only by the daily-reminders workflow |
| `dev/` | Work-in-progress copy of the homepage; published but not linked from the site |
| `firestore.rules`, `storage.rules` | Firebase security rules |

## Conventions

- Images go in `assets/`, never at the repository root.
- `assets/partners/partners.json` is generated by `.github/workflows/update-partners.yml` whenever anything
  in `assets/partners/` changes. Do not hand-edit it — drop the logo in and let the workflow regenerate it.
  Files ending in `_color.png` are ignored by that generator; only `N.png` and `N_white.png` are used.
- Build scripts live in `scripts/`, not at the root, and are excluded from the published site.
- Don't commit generated output (`_site/`, `node_modules/`); see `.gitignore`.
